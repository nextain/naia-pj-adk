# 표준 구성 선별 적용

## 채택

- 저장소 진입점과 프로젝트별 컨텍스트 분리
- GitHub 이슈 중심의 상태·증거 관리
- 역할과 실행 권한의 명시적 분리
- 실패 시 닫히는 배포·공개·중복 게이트웨이 정책
- 기계 검증 가능한 YAML 계약과 CI
- 배치 프로파일로 나눈 공통 계약 본체와 server·local 모듈
- 프로젝트 어댑터 템플릿
- 검수 후보의 커밋 SHA 고정
- 저장소를 큐로 쓰는 회차 프로토콜과 기기 등록부 (local 프로파일)

## 제외

- 개인 기억·비서·페르소나 중심 기능
- 특정 제품의 과거 요구사항과 진행 기록
- 특정 PC, 서버, 계정, IP, 토큰 정보
- 급여·특허·홍보 등 프로젝트 개발과 무관한 업무 스킬
- 벤치마크 제품과 메신저 실험 구현
- 다른 저장소의 Git 이력

## 배치 프로파일

이 저장소는 팀이 어디에 배치되는지를 `profiles/<이름>/` 디렉터리로 나눕니다.
server는 서버 한 대를 공유하는 팀이고 local은 각자 자기 기기에서 clone 받아
일하는 팀입니다. 브랜치로 나누지 않는 이유는 공통 계약을 고쳐도 한쪽에만
들어가고 두 쪽의 차이가 시간이 지날수록 커지기 때문입니다.

인스턴스는 어댑터에 `profile`을 하나 선언하고, 검증기가 그 프로파일의 요구만
적용합니다. 인스턴스가 실증에서 검증한 협업 모듈은 프로파일 모듈로 이 저장소에
올라옵니다. 기기 등록부와 회차 큐가 그 첫 사례입니다.

프로파일 모듈은 참조가 아니라 복사로 채택합니다. 인스턴스가 자기 계약의
소유자여야 하고, 상위 저장소의 파일이 조용히 바뀌어 인스턴스의 판정이 달라지는
일이 없어야 하기 때문입니다.

## 연결 방향

`naia-pj-adk`는 팀 프로젝트의 공동 규칙·권한·검증 계약을 담당합니다. 개인 작업환경
ADK와는 명시적인 어댑터로 연결하며, 한 저장소의 개인 설정·운영 자료·Git 이력을
다른 저장소로 복사하지 않습니다. 실증에서 확인된 원칙은 일반화된 계약과 안전한
예제로만 채택합니다. 자세한 범위와 독립성을 [계보 문서](LINEAGE.ko.md)에 기록합니다.
