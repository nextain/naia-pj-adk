# 공개 준비 상태

이 후보는 팀·프로젝트 단위로 재사용할 수 있도록 준비한 공개 ADK입니다. `LICENSE`는
Apache-2.0이고 `package.json`의 `private`는 `false`이며, 프로젝트 정책의 가시성은
`public`으로 맞춰져 있습니다. 이 값은 공개 준비 후보의 권리와 구조를 설명할 뿐,
원격 저장소의 visibility를 바꾸거나 공개 배포를 수행하지 않습니다.

공개 준비와 공개 완료를 구분합니다. 공개 완료에는 전체 트리와 도달 가능한 Git
이력의 사람 검수, 제3자 자료의 권리 확인, 그리고 소유자의 정확한 후보 커밋 SHA
승인이 필요합니다.

## 기계가 확인하는 것

- `node scripts/validate.mjs`가 필수 컨텍스트, 어댑터, 역할, `team_policy`, 라이선스,
  템플릿을 파싱합니다.
- `node scripts/adapter-contract.test.mjs`가 완전한 어댑터와 정상·거부 사례를 확인합니다.
- `node scripts/policy-guard.test.mjs`가 sender ID, 역할 그룹, 이슈 담당, 업무시간,
  production 승인·리비전과 실제 게이트웨이 위임 전 거부를 확인합니다.
- `ops/gateway/selftest.sh`가 게이트웨이의 정상·실패·런타임 가드를 확인합니다.
- `node scripts/public-safety-scan.mjs`가 현재 트리와 도달 가능한 모든 커밋·커밋
  메시지의 비밀·개인정보 형태를 검사합니다. 탐지된 값은 로그에 출력하지 않습니다.

어댑터 예제는 비활성 상태이고 실행 명령은 `null`입니다. 따라서 계약 검증은 실제
서비스 배포의 증거가 아닙니다. 활성화할 프로젝트는 각 대상의 게이트, 검증, 전파,
롤백 명령을 실제로 채운 뒤 별도 이슈에서 검증해야 합니다.

## 사람이 확인하는 것

`public_release.review_scope`에 따라 작업 트리, 숨은 파일, 생성물, 요구사항, 진행
기록, 로그, Git 이력·태그, 워크플로, 서브모듈, 라이선스를 함께 살핍니다. 이미지나
제3자 자료를 추가하는 downstream은 원래 출처·저작자·라이선스·상표 고지를 `NOTICE`
또는 해당 파일과 함께 보존해야 합니다. 참조용 제품 스크린샷과 별도 바이너리·원본
자료는 각각의 배포 조건을 확인하며, Apache 코드 라이선스를 자동으로 상속하지 않습니다.

공개 안전 검사에서 공식 공개 연락처처럼 보이는 과거 커밋 메시지가 탐지될 수도
있습니다. 정규식 결과만으로 비공개 정보라고 결론내리지 말고, 공개된 원출처와
문맥을 확인한 분류를 감사 기록에 남깁니다. 실제 자격증명, 사설 호스트, 고객 자료,
개인 식별자가 발견되면 공개를 멈추고 값은 기록·보고하지 않습니다.

## 신규 참여자 기준

첫 미션은 문서 수정이나 계약 테스트처럼 범위가 작은 이슈로 시작합니다. 참여자는
GitHub 계정과 자신의 fork, Node.js 20 이상, 이슈 담당자와 완료 조건, 브랜치 및
롤백 계획을 준비합니다. 자신의 fork를 HTTPS로 clone하고 이슈 브랜치에서 작업한
뒤 PR을 canonical 저장소의 선언된 통합 브랜치로 보냅니다. CI 통과는 검토·병합·
운영 배포를 뜻하지 않습니다.

고위험 변경은 구현자와 독립된 reviewer가 정확한 diff, 실행 명령과 출력, 영향 범위,
롤백, 동시 작업을 확인합니다. integrator가 통합하고 release owner가 별도 이슈
승인으로 production을 결정합니다.

## 공개 전 순서

1. `npm test`와 독립적인 실패·복구·신규 clone 시나리오를 실행하고 원시 stdout,
   stderr, 종료코드를 보존합니다.
2. 전체 트리·도달 가능한 이력·워크플로·운영 승인 파일·개인 프로젝트 경로를
   사람이 분류합니다.
3. 제3자 자료와 상표의 권리를 `NOTICE`와 함께 확인합니다.
4. 소유자가 검수한 정확한 후보 SHA를 승인합니다.
5. 그 뒤에만 원격 push, visibility, 템플릿·책·게시물 공개를 별도 절차로 진행합니다.

후보 준비 단계에서는 외부 시스템을 변경하지 않습니다. AI는 사람의 정확한 SHA
승인을 대신해 공개 완료를 선언하지 않습니다.
