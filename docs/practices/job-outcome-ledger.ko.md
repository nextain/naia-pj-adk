# 작업 결과 원장: 효과 불명은 다시 실행하지 않는다

범위: 공통
출처: onmam-dev `docs/discord-job-outcomes.md`, `docs/discord-parked-review.md`
상태: 온맘 조정자 확인 전

## 왜

모델 실행이 결과 기록에 실패해도 "검토 완료"를 게시할 수 있으면, 실제로 무슨 일이 일어났는지 아무도 모른다. 그 상태에서 다시 실행하면 같은 효과가 두 번 난다. 결과는 실행 장치가 따로 기록하고, 효과를 모르면 멈추고 대조한다.

## 규칙

1. 실행 장치는 모델을 시작하기 전에 자기 코드·설정을 고정한다. 모델 요청이 결과 저장소나 상태 파일 선택을 바꾸지 못한다.
2. 모델은 결과를 작업 전용 통로로 한 번 제출할 뿐, 정본 저장소에 직접 쓰지 않는다.
3. 실행 장치는 작업별 원장에 요청 해시와 `시작`을 먼저 디스크에 확정한 뒤 처리한다. 처리 결과는 `반영`(검사점 해시와 함께), `거절`, `불명` 중 하나로 남긴다.
4. 확인 응답이 사라져도 같은 요청에는 저장된 응답만 돌려준다.
5. `불명`·`시작`이 남아 있으면 같은 작업의 후속 요청과 새 실행을 막고, 실제 효과(저장소·상태 파일·도구 결과)를 대조한다. 원장을 지우고 다시 실행하는 복구는 없다.
6. 검토 작업은 원장의 `반영` 기록과 현재 검사점이 맞지 않으면 완료를 게시하지 않는다.
7. 되돌리기는 원장이나 데이터를 지우지 않고, 실제 작업을 재실행하지 않는다.

## 보류 정리에 같은 원칙을 쓴다

- 보류 여부는 명시적 상태 칸으로만 판정한다. 봇 요약의 `승인 / 보류` 선택 문구를 보류로 읽지 않는다.
- 잘못 들어간 보류는 원래 실행을 다시 시도하지 않고, 기존 효과와 사람 원문을 대조하는 검토를 한 번 접수한다.
- 원문 대조는 기록 직전에 다시 읽어 접수 때 해시와 맞춰 본다. 원문이 바뀌었거나 읽지 못하면 기존 보류를 유지한다. 기록 일부만 읽었으면 보류를 풀지 않는다.
- 에이전트가 할 준비(기록·목록·스냅샷)를 사람에게 요청한 답은 거절한다.

## 완료 증거

모델 실행 환경에서 저장소 직접 쓰기가 막히는지, 통로로 결과가 기록되는지, 검사점이 맞는지, 실제 전달이 한 번만 일어났는지를 각각 확인한다. 가짜 입력 시험은 실제 요청의 완료나 사람의 수신을 증명하지 않는다.
