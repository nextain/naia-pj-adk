# 작업 상태 계약과 이슈별 스레드

범위: 공통
출처: onmam-dev `.agents/context/development-process.yaml` (`onmam_bot_workflow.incident_default`의 `state_contract`, `thread_contract`, `actions_before_approval`)
상태: 온맘 조정자 확인 전

## 왜

봇 작업이 아무 표시 없이 멈추거나, 사람 확인을 기다린다는 기록 없이 서 있으면 누구도 알아채지 못한다. 작업이 가질 수 있는 상태를 몇 개로 못 박고, 그 밖의 상태는 업무 문제가 아니라 실행 장치의 장애로 판정한다.

## 허용 상태

| 상태 | 뜻 |
|---|---|
| 작업 중 | 실행자가 진행 중 |
| 확인 대기(추적 중) | 사람 확인을 요청했고, 요청 위치·대상·기한이 기록돼 있음 |
| 완료 | 반영·검증·보고까지 끝남 |
| 실패(알림 보냄) | 실패했고 담당에게 알림이 닿음 |

금지 상태: **조용히 멈춤**, **기록 없는 대기**. 작업이 이 상태가 되면 업무를 막는 것이 아니라 실행 장치(접수·배분기)의 장애로 판정한다. 배분기가 이어서 처리하고, 봇의 일을 사람 개인 메시지로 떠넘기지 않는다.

## 이슈별 스레드

- 이슈마다 메신저 스레드를 하나 만들거나 기존 것을 다시 쓴다.
- 조사·진행·승인 요청·검증·완료 증거는 그 스레드에 남긴다.
- 승인·사용자 확인을 기다리는 동안 스레드를 닫거나 작업을 완료 처리하지 않는다.
- 반영·검증·사용자 확인·최종 보고가 모두 끝난 뒤에만 스레드를 보관한다.
- 독립 감시가 짧은 주기(예: 5분)로 실행 장치 상태, 스레드 누락·잘못 닫힘, 승인·확인 기한을 검사한다.

## 승인 전에 할 수 있는 일

- 즉시 접수 확인과 영향 범위·심각도 판정
- 안전한 읽기 전용 진단과 재현
- 이슈 연결 또는 등록
- 수정 후보 작성과 로컬 시험
- 공유 자원을 바꾸지 않는 검증 환경이 있으면 반영·스모크 뒤 확인 요청
- 실행안·검증·백업·복구·정확한 명령을 완성한 뒤, 아직 없는 사람 판단만 대상 지정과 답변 양식으로 요청
- 승인 대기 중에도 큐를 막지 않고 상태·새 증거·무응답을 추적해 다시 보고

사람 확인 대기는 큐를 막지 않는다. 같은 이슈 안의 병렬 실행은 하지 않는다.
