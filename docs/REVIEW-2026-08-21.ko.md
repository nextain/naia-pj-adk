# 초기 적대 검수 기록

검수 대상은 다른 저장소의 이력을 복사하지 않고 새로 만든 `naia-pj-adk` 초기 후보입니다.

## 확인한 위험과 조치

| 위험 | 판정 | 조치 |
|---|---|---|
| 다른 프로젝트의 내부 이력·요구사항 유입 | 해결 | 빈 저장소에서 필요한 계약과 문서만 새로 작성하고 단일 루트 이력으로 구성 |
| Discord 메시지가 병합·배포 권한으로 오인됨 | 해결 | Discord는 조정 수단으로 한정하고 역할·이슈 승인을 별도 검사 |
| 동일 봇 토큰을 여러 게이트웨이가 소비함 | 해결 | 프로젝트당 앱 하나, 토큰당 소비자 하나, 중복 시 새 인스턴스 실패 종료 |
| DM 발신자 또는 별칭을 잘못 연결함 | 해결 | 무시되는 런타임 등록부와 JSON 스키마를 추가하고 미등록·중복 시 실패하도록 명시 |
| 비개발자가 작업 순서를 실행하기 어려움 | 해결 | SSH 작업공간, 브랜치, Codex/Claude, 커밋, dev 병합 요청 예시 추가 |
| 공개 검사에서 과거 Git 이력을 놓침 | 해결 | 현재 트리와 모든 도달 가능한 커밋을 함께 검사하도록 보강 |
| AI 도구별 규칙이 달라짐 | 해결 | `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` 바이트 동일성 검사 |

## 검증 결과

- 구조·미러·프로젝트 템플릿 검사: 통과
- 현재 트리와 도달 가능한 Git 이력의 민감정보 패턴 검사: 통과
- 기존 저장소 연결 없는 단일 루트 이력: 확인
- `review-pass` 복잡도 선행 검사는 비교할 부모 커밋이 없는 신규 저장소이므로 `NOT_RUN`
- 독립 외부 모델 교차 검수: `NOT_RUN`; 이 문서는 결정론 검사와 주 작업자의 1차 적대 검수 결과이며 독립 교차 검수 완료를 주장하지 않음

## 남은 경계

이 저장소는 비공개 상태로만 사용합니다. 공개 전환은 현재 트리와 도달 가능한 전체 이력을 다시 검사하고, 저장소 소유자가 정확한 후보 커밋 SHA를 승인해야 합니다. 실제 프로젝트의 서버·계정·참여자 ID·배포 명령은 이 저장소가 아니라 무시되는 런타임 설정 또는 각 비공개 프로젝트 어댑터에서 별도 검수합니다.
