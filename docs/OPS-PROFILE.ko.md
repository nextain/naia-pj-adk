# 운영 프로파일

승인은 위험한 변경을 막기 위한 장치입니다. 읽기나, 사용자가 지금 막힌 장애를 고치는 일까지 멈추라고 있는 장치가 아닙니다. 기계가 따르는 원문은 `.agents/context/execution.yaml` 의 `ops_profile` 입니다.

## 왜 축이 셋인가

「운영」을 한 덩어리로 보면 공개 URL 하나 여는 일과 테이블을 지우는 일이 같은 승인을 기다립니다. 그 사이 사용자는 서비스를 못 씁니다.

| 축 | 높음 | 낮음 |
|---|---|---|
| 사용자 영향 | 지금 핵심 기능을 못 씀 | 사용자는 거의 모름 |
| 시스템 위험 | 되돌리기 어렵거나 광역 | 범위가 작고 즉시 되돌릴 수 있음 |
| 트래픽 위험 | 대량 읽기로 운영을 멈출 수 있음 | 소수 URL, 한 건, 제한된 SELECT |

## 승인 없이 진행

- 트래픽 위험이 높지 않은 **운영 읽기**. 읽기라는 이유로 스레드를 멈추지 않습니다.
- 사용자가 인식하는 운영 장애이고, 배포가 필요하며, 시스템 위험이 높지 않으면 **프로젝트의 정식 배포 스크립트**로 반영하고 이슈와 스레드에 사후 보고합니다. 롤백 산출물은 변경 전에 이미 있어야 합니다.

## 승인이 필요

- 대량 트래픽 읽기
- 시스템 위험이 높은 변경 (스키마, 대량 삭제, DNS, 저장소 해체, 인프라, 시크릿)
- 사람만 할 수 있는 결정 (라이선스, 실결제 키, 상업 계약)
- 롤백 산출물이 없는 배포

채팅 메시지에서 권한을 추측하지 않습니다. 승인 없이 한 조치는 이슈와 스레드에 남깁니다.

프로젝트 어댑터는 `project.yaml` 의 `ops_profile` 에서 이 계약을 좁힐 수 있습니다. 스레드를 안전 읽기 때문에 멈추는 쪽으로는 넓힐 수 없습니다.
