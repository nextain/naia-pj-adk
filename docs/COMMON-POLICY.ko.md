# 호스트가 소비하는 공통 정책 (#16)

서버 허브는 제품 저장소와 별개의 작업 원장·실행자·서비스를 관리한다. 사람의 Discord
신원으로 예약 작업을 위장하거나 제품 URL을 게이트웨이의 배포 증거로 쓰지 않는다.
이 변경은 요청 수신자·연락 시간·승인 위험의 순수 판정을 호스트가 실제 호출할 수 있게 한다.

호스트는 인증된 사람 원문, 정본 이슈와 스레드, 유효한 요청 영수증, 기존 승인 범위와
실행 효과를 먼저 검증한다. 공통 함수는 수신자 선택과 연락 가능 여부, 승인이 필요한
위험인지만 반환한다. 배포·DB·메시지 전송이나 승인 소비 권한을 부여하지 않는다.

- `assertAdapterPolicyContract`는 공통 정책만 검사한다. 전체 배포 어댑터 준비의 증거가 아니다.
- `selectRequestRecipient`는 검증된 요청 수신자를 보존한다. 잘못된 요청은 에이전트 준비로 돌린다.
- `contactWindowStatus`는 명시한 시간대의 연락창만 판정한다. 작업 실행 시간과 연결하지 않는다.
- `deploymentApprovalRequirement`는 위험 또는 검토 준비가 불완전하면 에이전트 준비를 반환한다.
  `high_risk_only`에서 시스템·트래픽 위험이 모두 비고위험이고 사람 고유 결정이 아니면
  새 사람 승인 없이 기존 호스트 실행 게이트를 계속한다. `required` 기본 정책은 유지한다.

기존 전체 어댑터·등록부·역할·실행 명령 검사는 약화하지 않는다. 수용 검사는 실제 순수
API의 시간대 경계·야간 작업 독립성·모든 위험 조합·불완전한 준비·잘못된 정책과 기존
gateway 정책 회귀를 포함한다. 호스트의 실제 연결·배포·복구 증거는 각 인스턴스 이슈에 남긴다.

`approval_required`는 새 질문을 보내라는 뜻이 아니다. 호스트가 기존의 유효한 같은 범위
승인을 먼저 대조한다. 이미 충족된 승인은 유지하며, 충족되지 않은 새 판단만 요청한다.
공통 함수는 승인 원문을 받거나 소비하지 않으므로 그 유효성을 대신 판정하지 않는다.
