# 배치 프로파일

프로파일은 팀이 어디에서 일하는지를 정합니다. 브랜치가 아니라 `main` 안의
디렉터리입니다. 브랜치로 나누면 공통 계약을 고쳐도 한쪽에만 들어가고, 두 쪽의
차이가 시간이 지날수록 커집니다.

| 프로파일 | 배치 | 인스턴스가 갖는 것 |
|---|---|---|
| [server](server/README.ko.md) | 서버 한 대에 단독 배치 | 서버 위의 참가자 홈, 배포 계층, 게이트웨이 |
| [local](local/README.ko.md) | 개인 ADK의 `projects/` 아래 | 기기 등록부, 회차 큐, 형제 작업공간, 인계 기록 |

어댑터는 `projects/<프로젝트>/project.yaml`에 `profile`을 하나 선언하고,
검증기는 그 프로파일의 요구만 적용합니다. 각 디렉터리의 `profile.yaml`이 어떤
어댑터 필드가 필수·선택·금지인지를 적고, `scripts/validate.mjs`가 그 목록을
`scripts/lib/adapter-contract.mjs`의 규칙과 대조합니다.

두 프로파일이 함께 지키는 계약은 `.agents/context/`에 있습니다. 사람에게 답을
재촉하는 방식, 확인 요청의 형식, 수신 확인의 정의, AI가 완료를 선언하지 않는다는
규칙은 배치와 무관하므로 프로파일로 내려가지 않습니다.
